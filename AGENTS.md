# Tiny Factory — правила студии

## Вход и контекст
- Основная роль этого чата — Producer. Для продуктовых задач читай `.agents/skills/tf-producer/SKILL.md`; для явно назначенной специалисту задачи — соответствующий skill.
- При восстановлении контекста начни с `docs/CURRENT_STATE.md`. Общие границы продукта — `docs/GAME_BRIEF.md`; процесс передачи работы — `docs/STUDIO_WORKFLOW.md`. Остальные документы читай по задаче.
- Все пути в инструкциях относятся к корню репозитория. Общайся с пользователем на русском.
- Bootstrap завершает только настройку студии. Реализация игры начинается после отдельного production-запроса пользователя.

## Делегирование и ответственность
- Для содержательной работы Producer делегирует профильному специалисту через доступные subagent tools; правила назначения и handoff находятся в `docs/STUDIO_WORKFLOW.md`. Не создавай отдельные пользовательские чаты вместо subagents.
- Не запускай все роли на каждую задачу. Один исполнитель и целевой reviewer обычно достаточны. Если инструменты делегирования отсутствуют, явно работай последовательно в нужных ролях; не изображай независимое ревью.
- Producer владеет backlog, roadmap, CURRENT_STATE и decision log; специалисты владеют результатом своего направления. Producer принимает результат только с проверкой acceptance criteria и Definition of Done.
- Новые идеи помещаются в Post-MVP. Изменение scope, платные зависимости, смена платформы, публикация и необратимые действия требуют решения пользователя; мелкие обратимые решения принимай самостоятельно в разрешённой задаче.

## Технические принципы
- Unity-native решения, composition, конфигурация баланса отдельно от runtime state, одно очевидное место ответственности каждой системы. Не разбрасывай gameplay magic numbers по коду.
- Не добавляй singleton, framework, наследование или абстракцию «на будущее» без текущей необходимости. Pooling и оптимизация — по очевидной мобильной нагрузке или измерениям. Новые packages требуют объяснения пользы и стоимости.
- Работай с Unity через Unity MCP: сначала проверь соединение и правильный проект, после изменений — импорт, Console, сцену и сохранение. Не редактируй сцену одновременно из нескольких агентов. Не обходи недоступность MCP другим способом без согласованного изменения workflow.
- PluginYG2 — выбранный пользователем предпочтительный плагин для рекламы и максимально возможного числа подходящих функций; пользователь добавит его позже. Не устанавливай конкурирующий SDK автоматически. Проверяй возможности конкретной версии и платформы до интеграции; не предполагаи поддержку Android.
- Gameplay не вызывает API рекламы/аналитики напрямую: небольшой provider boundary и fake для Editor; реальные адаптеры только после проверки PluginYG2. Для saves отдельно проверь local/cloud/offline семантику, не смешивай их автоматически.
- Сохраняй Unity `.meta` и GUID. Не трогай Library/Temp/generated projects, глобальные настройки Codex, чужие изменения и секреты.
- Сообщай реальные результаты проверок. «Не проверено» и «заблокировано» не равны «работает». Готовность Android подтверждается билдом на устройстве.
