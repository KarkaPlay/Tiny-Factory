## Фантазия и границы

Игрок постепенно строит уютное чайное предприятие: собирает свежий лист, сушит его, распределяет сушёный чай между заказами и фасовкой, а монеты вкладывает в производственные улучшения. Экран — portrait с фиксированными участками (plots), вертикально расположенными в порядке цепочки. Каждое здание показывает собственные вход, работу и выход.

**Пилот:** 3 производственных узла — чайный сад → сушильня → фасовка. Одна валюта (монеты), три продукта (FreshLeaf, DryTea, TeaPacket), два заказа на выбор и один активный заказ. В пилоте нет автоматической продажи/передачи между узлами: игрок вручную забирает выход в общий склад и вручную загружает вход следующего узла. Деньги приходят только за закрытый заказ.

Пилотная цель: построить все три узла и закрыть контрольный смешанный заказ `DryTea ×2 + TeaPacket ×2` за 22 монеты (`2×5 + 2×6`). Он становится гарантированным предложением после постройки фасовки; сохраняется на board до принятия, не истекает и не мешает пользоваться вторым предложением. После hand-in показать «Базовая цепочка готова»; заказы и upgrades продолжаются, expansion chapter не открывается в active pilot.

**После пилотного gate:** конечные главы и общий потолок 4–5 fixed plots, без бесконечного набора зданий. Кандидат на четвёртый узел — подарочная упаковка `TeaPacket → GiftTea`; возможное ответвление пятого — прессование `DryTea → PressedTea` из того же промежуточного продукта, без нового источника трав. Оба кандидата **не готовы к балансу и не входят в пилот**. Только после review данных и решения пользователя можно выбрать, добавлять ли ветку. Автоматизация маршрутизации может позже сокращать рутину. В пилоте нет авто-переноса и авто-сбыта.

## Ресурсы, рецепты и производственные правила

| Узел / SKU | Правило | Локальный предел |
|---|---|---:|
| Чайный сад → FreshLeaf | 1 лист каждые 15 foreground-секунд; производство останавливается при полном output | Output 8 |
| Сушильня: FreshLeaf → DryTea | Рецепт 2 FreshLeaf → 1 DryTea; 8 секунд на единицу результата | Input 8, WIP 1 рецепт, Output 8 |
| Фасовка: DryTea → TeaPacket | Рецепт 1 DryTea → 1 TeaPacket; 6 секунд на пакет | Input 8, WIP 1, Output 8 |

Все новые партии идут только вперёд через warehouse и ручную загрузку. Запуск работы атомарно потребляет полный рецепт из локального input и создаёт один WIP; это единственная reservation. Один WIP на здание; завершённый WIP остаётся там, если нет места в output. Полный output останавливает станок/сад с видимым статусом; предметы не удаляются.

Общий склад: 40 предметов суммарно, максимум 20 на SKU. Начальный fresh inventory: 4 FreshLeaf (4 LE). Локальный предел input/output каждого перерабатывающего узла — 8 единиц; садовой output — 8; один WIP на узел. Wallet max `1_000_000_000_000` coins; each quantity max20 per SKU in warehouse and configured local cap. Перенос — явная команда количества; collect и load атомарны: либо перемещается всё выбранное количество, либо ничего. Система может предложить «забрать всё, что помещается» как рассчитанную кнопку, но результат до нажатия виден. Потерянных частичных партий нет. Загрузка одного станка не резервирует склад под заказ; баланс проверяется повторно в момент команды.

В foreground производят все открытые/построенные узлы. Узел без input не продвигает работу; закрытый или ещё не построенный узел не производит. Пассивный процесс в background/cold return описан в Save semantics; заказы там не закрываются и деньги не начисляются.

## Заказы и экономика

Доска содержит 2 предложения; одновременно активен максимум 1 заказ. Fresh save получает onboarding offer `FreshLeaf ×4`; второй слот допустим по текущим milestones. После tutorial слот1 всегда содержит доступный FreshLeaf order (количество 1–5), слот2 — случайный допустимый заказ на1–2 SKU уже построенных производств, по1–5 единиц каждого. После постройки фасовки слот2 становится гарантированным mixed pilot order `DryTea ×2 + TeaPacket ×2`, reward22. Он не истекает и не может быть заменён до выполнения; если игрок бесплатно отменяет его до hand-in, тот же контракт возвращается в слот2 с новым offer ID. Пока mixed order активен, слот2 заполняется обычным случайным предложением, а не второй копией учебного контракта. При отмене активного mixed order специальное предложение возвращается в слот2 с новым ID вместо обычного. После hand-in устанавливается сохранённый `pilotGoalComplete`; специальный контракт больше не создаётся, слот1 сохраняет FreshLeaf fallback. Выбор любого offer атомарно удаляет его из board и выдаёт замену с новым уникальным ID; доска остаётся с двумя предложениями плюс один active order. Игрок может бесплатно отказаться от active order; ни отказ, ни замена обычного slot2 offer не расходуют товары. Выплата только при полном атомарном закрытии: warehouse проверяется и все требуемые количества сразу списываются, после чего начисляется одна награда. Ничего не резервируется при выборе заказа; сырьё до hand-in можно использовать в зданиях. Нет частичной сдачи, скрытого escrow, комиссии, штрафа или выплаты за отказ.

Цена каждого продукта считается из leaf-equivalent и числа производственных шагов; числовые единицы: FreshLeaf=1 LE/0 шагов, DryTea=2 LE/1 шаг, TeaPacket=2 LE/2 шага. Награда заказа = сумма по всем единицам `ceil(2 × LE + число шагов)`: 2 монеты за FreshLeaf, 5 за DryTea, 6 за TeaPacket. Сад возобновляемо производит сырой FreshLeaf — это заданный источник пилота. В пилоте нет входного магазина, покупки FreshLeaf, продажи зданий или другого конвертера, создающего арбитраж. Заказ на набор равен сумме строк — бонус комплекта не добавляется.

Слот1 FreshLeaf генерируется из фиксированной допустимой последовательности и не заменяется; обычный слот2 выбирается детерминированным saved RNG из допустимых наборов. Исключение — guaranteed mixed pilot order после открытия фасовки, пока hand-in не завершён. Если этот заказ отменён, повторная offer entry получает новый уникальный ID, прежний больше не принимается. Seed/state, offer IDs и сами предложения сохраняются транзакционно после генерации/замены/принятия/отмены. Игрок может бесплатно заменить обычный слот2; замена не выдаёт предметы/монеты и выдаёт следующий результат сохранённой последовательности. Reload не откатывает RNG или замену. Поскольку награда фиксирована по содержимому, перебор обычных предложений меняет предпочтительный маршрут, но не даёт прибыльного reroll.

Активный заказ можно выбрать при любом текущем запасе и собирать недостающее; hand-in разрешается только когда warehouse покрывает весь набор. Ничего не резервируется и не списывается до полного закрытия. Случайные заказы содержат только SKU построенных производств (одного unlock без покупки недостаточно); слот1 всегда FreshLeaf, так что можно получить деньги до открытия следующих станций и после неудачных трат. Наборы ограничены складской ёмкостью.

## Постройки, unlocks, upgrades

Один фиксированный plot на узел; строительной валюты/материалов кроме монет нет. Сад открыт и построен при старте, сушильню можно построить сразу, фасовка становится доступна после milestone. Входные ресурсы и выпуск сами по себе не генерируют деньги — нужен заказ. Покупка влияет на новые циклы; in-flight WIP сохраняет исходное remaining time.

| Объект/уровень | Цена | Требование | Эффект / предел |
|---|---:|---|---|
| Стартовый кошелёк | 80 | Fresh save | Один раз; не возобновляется при возврате |
| Сад | Бесплатно | Старт | 1 FreshLeaf/15с; output cap 8 |
| Сушильня (постройка) | 40 | Старт | Включает рецепт 2→1 DryTea |
| Сушильня L1 | 45 | Сушильня построена | 6с на DryTea |
| Сушильня L2 (MAX) | 90 | L1 | 4с на DryTea; конечный уровень |
| Фасовка (постройка) | 70 | Произведено 5 DryTea суммарно | Включает рецепт 1→1 TeaPacket |
| Фасовка L1 | 55 | Фасовка построена | 5с на TeaPacket |
| Фасовка L2 (MAX) | 110 | L1 | 4с на TeaPacket; конечный уровень |
| Сад L1 | 30 | Старт | 1 FreshLeaf/12с |
| Сад L2 (MAX) | 65 | L1 | 1 FreshLeaf/9с; конечный уровень |

Milestone «произведено 5 DryTea» считает завершённый выпуск сушильни за всё время, не количество, хранящееся сейчас. Узел открывается один раз и не закрывается при продаже/использовании товара. Покупка атомарна: проверка денег и уровня, списание и изменение уровня — единая транзакция. Если монет не хватает, upgrade/build остаётся виден с дефицитом. На MAX повторной кнопки нет. Запущенная работа сохраняет исходный timer; новая длительность действует для следующего WIP.

## Короткая проверка числового пути

Числовая проверка кошелька: `80 + (4 FreshLeaf × 2) − 40 = 48`; `48 + (5 DryTea × 5) − 70 = 3` после постройки фасовки. Денежный путь сходится без дополнительных валют. Проверочная foreground-трасса при manual collect/load на первом доступном тике, source cap8, input cap8 и без overflow:

1. Fresh save: 80 монет и 4 FreshLeaf (4 LE). Закрыть гарантированный onboarding-заказ `FreshLeaf ×4` → +8, wallet 88.
2. Построить сушильню за 40 → 48 осталось; fresh inventory пуст. Это оставляет денежный recovery route, даже если игрок потратил кошелёк на постройку.
3. На t15,30,…150 сад выдаёт 10 FreshLeaf. Вручную загружать по 2 на тиках t30,60,90,120,150; сушильня выдаёт DryTea на t38,68,98,128,158. Загрузка/input batch не превышает 8, Garden output максимум8 и освобождается collect. Заказ `DryTea ×5` из допустимого seeded offer закрывается на t158 → +25; wallet73.
4. После пятого произведённого DryTea фасовка открыта; построить её за 70 → 3 осталось. Пилотная цепочка доступна без принудительной покупки рекламы/внешней валюты. Это 14 FreshLeaf суммарно (4 заказу, 10 в сушилку); прогноз времени — этот ручной trace, не retention/fun target.
5. Дальше одинаковые 2 FreshLeaf дают выбор: закрыть DryTea order за 5 монет либо провести единицу через фасовку и закрыть TeaPacket order за 6. Один extra coin за дополнительную операцию — слабое, непроверенное преимущество; пока фасовка не имеет иных спросовых/производственных плюсов. Если предложение на набор содержит оба SKU, часть DryTea можно оставить на складе, остальное направить в фасовку. Acceptance test должен спросить, какой из двух заказов/маршрутов игрок выбрал и почему; дизайн не утверждает, что choice уже compelling.

Это проверка арифметики достижимости, не симуляция реальной скорости сессии: реальный срок зависит от taps, лимитов склада, handoff batch и ожидания заказов. Проверить на прототипе, не становится ли фасовка обязательной тупиковой покупкой; даже при нуле монет сырьевой FreshLeaf order остаётся денежным источником. Ни fun, ни retention, ни pacing не считаются доказанными.

## Первый путь игрока и возвращение

**Первые 60 секунд:** (0–5с) показать вертикально расположенный сад, начальные 4 FreshLeaf в общем складе и два заказа; действие — закрыть гарантированный заказ `FreshLeaf ×4`, получить +8. (5–15с) построить сушильню за 40; wallet 48. Сад выдаёт FreshLeaf на t15 и t30. (t30) забрать 2 листа и загрузить их в Dryer; показать timer 8с и локальный input. (t38–45) забрать первый DryTea в склад и показать бесплатную замену обычного случайного предложения. (t45–60) собрать ещё 2 листа, показать их в складе и следующий milestone «произвести 5 DryTea»; после загрузки на t60 следующий DryTea будет готов на t68. Заказ не резервирует товары; после постройки фасовки открывается гарантированный mixed pilot order.

**Возврат:** active pilot пока не обещает offline production. После обычного сохранения отобразить накопленные монеты, локальные/складские запасы, текущий WIP/остаток, активный заказ и два предложения. Следующую команду подсказать через collect, load, finish order, build или upgrade.

## Save, offline и миграция

Это предложение меняет старую cold-load семантику D11; offline не входит в active pilot. **0.5 пилот:** сохранять и восстанавливать WIP/timers, но не прибавлять elapsed production после закрытия приложения; local save и migration проходят отдельный 0.5 gate. **0.6 кандидат:** elapsed offline production с wall-clock cap8h. При текущих caps сад останавливается после 8 FreshLeaf (не более 2 минут генерации без collect), поэтому 8h почти не дают дополнительного результата; Dryer/Packer также остановятся на локальных limits, offline order hand-in отсутствует. Offline profile сейчас **UNREADY, блокирован на отдельном balance/capacity review**: нельзя переносить fast foreground profile на elapsed time. До 0.6 gate отдельно выбрать slower production profile и утвердить local output/input/storage capacities с полезной return-трассой. Только после этого можно обещать return summary. Гипотеза алгоритма после gate: elapsed=min(valid persisted UTC delta,8h), симулировать только production, без auto collect/load, order completion или денег; checkpoint новое состояние и UTC timestamp. Clock rollback/forward, timezone/DST, force close и длинный перерыв требуют device verification. Не считать текущий 8h wall cap восемью часами производственной пользы.

Минимальные gameplay fields: `coins` (cap1e12), `builtStations`, `upgradeLevels`, `warehouseBySku`, `stationInputs/Outputs` (local cap8 per SKU), `wipRecipeAndRemainingTime`, `lifetimeDryTeaProduced`, `pilotGoalComplete`, `ordersBoard`, `activeOrderId`, `rngState`. Shared warehouse cap40 total/20 per SKU. Общие настройки/версия/проверки состояния принадлежат save contract. Все SKU quantities и money ограничены конечными целыми; отрицательные, переполненные или неизвестные значения отклонять/восстанавливать контролируемо.

Gameplay требует локальное версионированное сохранение по D15: каждая операция (order hand-in, build/upgrade, stock transfer, offer replace, production completion) восстанавливается целиком до или после commit, без двойного начисления/списания. Production state persistent; это отличается от M01 cold-WIP discard. Поля schema, backup/recovery и legacy migration конкретизируются в отдельном `META_SAVE_CONTRACT.md`; эта spec не утверждает миграционный маппинг и не разрешает реализацию.

Legacy migration и совместимость economy profile следуют принятому пользователем META_SAVE_CONTRACT и остаются за пределами fresh balance-трассы этого документа. Миграционный профиль получает стартовый запас `4 FreshLeaf / 4 LE` один раз по новой конфигурации, но не дополнительный fresh-save bonus `80 coins` поверх импортированного wallet; точный mapping старых coins/refunds относится к save contract. Game Designer не считает migration-профиль эквивалентом нового игрока. Реализация0.5 запущена; миграция ещё не подтверждена runtime-проверками.

## Не входит

В пилот не включены: perish/spoilage, deadlines/FOMO, prestige, вторая валюта, социальные механики, real ads, новые ветки, динамическая карта/расстановка зданий, входной магазин, авто-маршрутизация, автосбыт, сезонные события, бесконечные уровни. Chapter/gift packaging и ещё одна ветка — только после пилотного gate. Реклама не является условием прогресса.

## Acceptance criteria

**Для реализации:**

1. Сад→сушильня→фасовка видны сверху вниз; в пилоте ровно три fixed plots. Ни один item не переходит между local storage и warehouse автоматически.
2. Все указанные рецепты, времена, limits, milestones, цены и upgrade эффекты читаются из конфигурации; runtime state отделён от баланса.
3. Collect/load whole-quantity transaction либо перемещает всё выбранное количество, либо ничего. Full output блокирует выпуск с видимым backpressure, без item loss.
4. Two persistent offers + one active order; отсутствие сроков; бесплатная замена обычного случайного offer; уникальные IDs при atomic accept/refill/cancel; один полный atomic hand-in. Reload не откатывает замену или RNG; order не начисляет монеты дважды.
5. DryTea можно сдать заказом либо вручную загрузить в фасовку. Игрок может словами объяснить оба маршрута и видит баланс товаров до действия.
6. При нулевом кошельке доступен FreshLeaf fallback order; строительство/upgrade/заказ не создают soft lock. Пилотный расчёт: 80→88 после заказа FreshLeaf ×4 → 48 после Dryer build → 73 после DryTea ×5 order → 3 после Packer build.
7. После постройки трёх узлов появляется mixed pilot order `DryTea ×2 + TeaPacket ×2`, reward22; закрытие списывает полный комплект атомарно и отображает «Базовая цепочка готова». Заказы и upgrades остаются доступны после goal.
8. Повторное открытие восстанавливает stock, WIP, two board offers + active order, RNG, milestones и upgrade levels без двойных транзакций. В 0.5 нет elapsed offline simulation.
9. Legacy migration проходит отдельный save contract/user review в 0.5. Runtime/Unity/Android проверка этой design-задачей не выполнялась.

**Пилотный user playtest hypotheses:**

1. Новичок за первую минуту может показать, где лежит общий склад, как загрузить сушильню и как забрать выход; если нет — UI/flow review до расширения.
2. Игрок понимает, что один DryTea можно либо отдать заказу за 5, либо пустить в фасовку ради TeaPacket заказа за 6. Это слабое ценовое преимущество; игрок проговаривает спрос/запасы, не предполагая, что фасовка автоматически выгоднее.
3. Участник с нулём монет способен обнаружить FreshLeaf fallback order и снова заработать; timeout/fail/reload не лишают запаса или награды.
4. После постройки Packer игрок завершает контракт DryTea×2 + TeaPacket×2 и может объяснить, почему один продукт остался в warehouse, а другой ушёл на фасовку.
5. Измерить активное время открытия/покупки всех трёх узлов, число collect/load taps, отклонённых transfer, полные склады и abandon order. Числа являются наблюдением, без заранее выдуманных target для retention/fun.
