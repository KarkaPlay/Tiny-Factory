# M051 — быстрые передачи, scroll snap и производственный feel

**Статус:** implementable UI brief для 0.5.1 / code12; scope одобрен пользователем. Основа — [META_UI_SPEC](META_UI_SPEC.md), [META_GAMEPLAY_SPEC](META_GAMEPLAY_SPEC.md) и действующий save2 contract. Реализацию и actual image/animation evidence проверяет Producer после Engineer; ручной device review обязателен.

## Цель и границы

Сделать движение по вертикальной фабрике предсказуемым, а частые передачи — доступными прямо у здания. Подчеркнуть движение продукта и работу машин короткими визуальными эффектами. Экономика, рецепты, заказы, правила вместимости и атомарности действий, save2 и отсутствие автопередач остаются прежними. Не добавлять новые пакеты, платные ассеты, игровые механики или автоматизацию.

## Экран и участок

- Сохранить portrait-компоновку: фиксированные верхний HUD и нижняя вкладка/карточка в safe area; центральный world viewport вертикально прокручивается между ними. Здания остаются одной фиксированной колонкой в производственном порядке.
- Во время scroll автоматически вести selection за ближайшим видимым зданием в полезной области viewport между HUD и нижней панелью; использовать небольшой hysteresis около границы соседних участков, чтобы selection не дрожал. По release прокрутить к snap-позиции ближайшего участка и окончательно подтвердить выбор. Не уводить его под панели; на краях clamp к допустимому диапазону. Tap по зданию выбирает его без pan. Drag, начатый на HUD, карточке или любом интерактивном элементе, не двигает поле.
- Offset сохраняет действующий numeric meaning: clamp существующего world offset в диапазоне `−12..0`, без переинтерпретации как `0..1` и без migration. Записывать только settled offset после завершения snap; при восстановлении clamp, snap к ближайшему допустимому участку и выбрать его. Формат/schema save2 не менять.

## Быстрые действия у зданий

У каждого доступного здания показывать компактные world-space действия с читаемой подложкой и минимумом 48 dp для интерактивной области. Они следуют за зданием при pan и не перехватывают scroll: pan начинается только при drag из свободной области мира; нажатие кнопки выполняет действие. Карточка выбранного узла остаётся для деталей и улучшений, но больше не открывает transfer picker.

| Узел | Действия | Правило |
|---|---|---|
| Сад | `Забрать N` | Перемещает весь доступный FreshLeaf output, который помещается на склад. У сада нет действия загрузки. |
| Сушильня | `+1` / `Забрать N` | `+1` переводит ровно 1 FreshLeaf со склада во вход. Существующий рецепт требует 2: при 1/2 показывать ожидание второго листа; не запускать рецепт и не округлять действие до двух. `Забрать N` переносит весь помещающийся DryTea. |
| Фасовка | `+1` / `Забрать N` | `+1` перемещает ровно 1 допустимый входной SKU по действующим правилам рецепта; `Забрать N` переносит весь помещающийся TeaPacket. |

`N` — фактическое количество, которое можно забрать сейчас: `Забрать 0` заменяется disabled состоянием с причиной, а при частичном месте кнопка показывает, сколько будет собрано. Оставшийся выпуск остаётся в здании. Load недоступен, если склад пуст, вход достиг вместимости, здание закрыто или игровое состояние запрещает приём; collect недоступен, если нет выхода/места. Причину кратко показывать рядом с действием, не только цветом. Перед commit UI использует актуальные stock/capacity данные. Успех подтверждается числом/иконкой и обновлёнными локальным и складским счётчиками; отказ не меняет количество и показывает исправимую причину. Повторный tap после завершения действия выполняет новое отдельное действие, без двойного расхода.

Внизу остаются сведения о выбранном здании: вход и локальный запас/требование рецепта, работа/WIP с прогрессом, выход и статусы; upgrade/цена/эффект доступны там же из game data. Transfer picker и отдельное подтверждение количества убрать. Кнопки зданий не дают cashout и не запускают передачу между станциями.

## Motion и progress feedback

Визуальные эффекты следуют только за успешным игровым commit; gameplay state и числа обновляются сразу, а анимация служит подтверждением. Переиспользовать текущие объекты/иконки, материалы и подключённый DOTween. Не создавать скрытые запасы, не задерживать commit до конца tween и не показывать движение, если операция отклонена.

- **Сбор:** подсветить выход здания и общий склад, затем показать компактное движение N единиц по понятной дуге/траектории source → depot. Обновить складской индикатор; остаток в здании виден, если cap ограничил сбор.
- **Загрузка:** показать движение одной единицы depot → целевой вход/приёмник, затем короткий акцент на входном индикаторе. Для сушильни после первой из двух единиц показать `1/2`, `Нужен ещё 1 FreshLeaf` и ожидание; после второй commit запускает обычную производственную симуляцию.
- **Производство:** во время работы видимо дать движение/ритм самому объекту или его рабочей части (например, лёгкий цикл, вращение или squash/settle) и заполнение прогресса. На завершении показать готовый output у выхода с коротким pulse; корректно отображать одновременно новый WIP и готовый предыдущий output, если это допускает состояние.
- Показывать связь производств через общий склад: визуальное действие сбора ведёт source → depot, загрузки — depot → receiver. Игрок видит товар, перемещающийся между источником/складом/приёмником в контексте ручной операции; постоянного авто-flow и скрытых межстанционных передач нет.
- Короткие эффекты не закрывают статусы и цифры; по умолчанию не требуют новых частиц или звука. При повторном действии, смене selection, сворачивании/потере фокуса или завершении tween корректно остановить/свести FX к фактическому состоянию. Background не оставляет зависшее движение.

## Состояния

- `Готово к сбору`: `Забрать N` активно, если есть место. `Частично помещается`: показать собираемое N и локальный остаток после операции.
- `Нет выхода` / `Нет места на складе`: collect отключён с краткой причиной; объект и числа остаются стабильны.
- `Можно загрузить`: `+1` активно. `Недостаточно товара` / `Вход заполнен` / `Здание закрыто`: disabled с конкретной причиной.
- `Ожидает рецепт`: Dryer input `1/2 FreshLeaf`, progress производства не стартовал; доступно загрузить вторую единицу.
- `Работает`: видимый progress из gameplay state и ненавязчивый цикл машины. `Готов выпуск`: отдельный output chip; он не скрывается при наличии работающего WIP.
- `Не выбрано/selection`: после snap выбран ближайший участок; карточка синхронно показывает его данные. Выбор и состояние кнопок не меняются от декоративной анимации.

## Acceptance / evidence

1. На portrait viewport drag отпускается с предсказуемым snap в видимую область; ближайшее здание выбрано, selection не дрожит на границе. Панели и кнопки не начинают pan; tap по зданию выбирает его.
2. Сохранённый world offset в прежнем числовом диапазоне `−12..0` восстанавливает ближайший участок, UI selection согласована; формат save2 и gameplay state совместимы с текущим контрактом, migration не требуется.
3. Быстрый collect показывает точный помещающийся N, сохраняет остаток при cap; быстрый load перемещает ровно 1 допустимую единицу. Economy, рецепты и order quantities не меняются.
4. Dryer при 1/2 FreshLeaf остаётся в ожидании; после второго листа ведёт себя как прежний рецепт 2 FreshLeaf. Отсутствие товара/места/доступа не коммитит действие.
5. После успешных collect/load видны корректные направления source → depot и depot → receiver. Нет анимации/функции автопередачи между зданиями. После failed commit нет ложного визуального движения.
6. Работа и готовый output имеют заметный, но не отвлекающий progress/finish feedback; числа и статусы читаемы при движении и повторном действии. Interruption/foreground resume не оставляют tween в неверном состоянии.
7. Перед handoff Engineer прикладывает actual runtime image/animation evidence для collect, load, Dryer 1/2→2/2, production/output, scroll snap и частичного cap. Designer/Producer проверяет эти фактические кадры/клипы. Mobile приемка отдельно подтверждается ручной проверкой hardware: safe area, touch/scroll arbitration, tap targets ≥48 dp, portrait 9:16, 19.5:9 и 20:9; до неё device UX не считать подтверждённым.

## Handoff

**Следующему:** Engineer реализует UI/input/presentation M051 и при необходимости расширяет transfer API для атомарной загрузки ровно 1 SKU; производственный рецепт Dryer по-прежнему запускается только при существующих 2 FreshLeaf. Не менять баланс, рецепты, заказы и save2 contract. После implementation предоставить перечисленные actual image/animation evidence Producer для review; UI Designer остаётся read-only reviewer этих фактических кадров/клипов. Producer ведёт общие project/status документы и организует последующую проверку.

**Не проверено здесь:** Unity runtime, сцена, build, actual captures и физическое устройство.
