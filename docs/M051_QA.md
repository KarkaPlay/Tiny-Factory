## Условия и изоляция

- Unity — только через MCP после handoff; подтвердить правильный проект, версию Unity/platform и чистое состояние сцены/Console. Один последовательный run.
- Любые runtime fixtures — отдельные disposable hidden hosts и private temp save paths. Не менять production save, persistent files, сцену/префабы или игровые исходники. Удалять fixtures в `finally`; фиксировать фактическую очистку.
- Для каждого case записать setup → action → expected → actual → evidence. Допустимые статусы: PASS, FAIL, NOT RUN, BLOCKED. Скриншот/клип подтверждает appearance, но не заменяет проверку state/conservation.
- Baseline: текущий save2 schema и source v1 migration из M050. Не считать Editor evidence проверкой физического Android.

## Подготовка к исполнению

Latest source прочитан read-only. `MaxLoad` допускает 1 единицу, `TryStartProcessing` начинает Dryer только при полном recipe size, `LoadOne()` передаёт в runtime ровно 1, а `TransferCommitted` вызывается после успешного transaction. Quick action подписывает callbacks отдельно; WorldView держит selection preview в памяти и пишет `SetUiState` на завершении snap. Quick-action drag threshold отключает eligible click после 12 dp; pause/focus path очищает pointer и сразу settle-ит позицию. Это source review, не runtime PASS.

Исполнение: Unity 6000.3.9f1, Android project target, active `SampleScene`, Edit Mode. In-memory C#6 fixtures использовали hidden disposable hosts и private temp save paths в `/private/tmp`; проектные source, scene и production save не редактировались. Все fixture directories удалены в `finally` (проверка `find` вернула пустой список). После FX fixture в Console были несколько **Error** entries `Destroy may not be called from edit mode!` из `KillFlight` при cleanup косметического token на hidden Edit Mode host, плюс ожидаемый access-denied от намеренно сломанной записи save fixture. Ранее существовали MCP transport warnings. Scene validation до запуска: 0 issues. Fixture initialization вызывала lifecycle callbacks вручную, так как execute-code не продвигает rendered frame в Edit Mode.
