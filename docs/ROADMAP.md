# Roadmap

Отсчёт — с начала production, не с bootstrap. Базовый план: 10 рабочих дней; до 5 дней резерва. Это оценка одного разработчика с виртуальными специалистами, не обещание параллельной скорости. Дни включают review и исправления.

0.1.0 принят 2026-10-05 как документный результат M01: [GAMEPLAY_SPEC](GAMEPLAY_SPEC.md), review UI/Monetization, QA PASS согласованности и воспроизведённая расчётная трасса. Игрового билда ещё нет. Остальные версии ниже — целевые, ещё не выпущенные. Scope и оценки сроков сохраняются; версия обозначает принятый результат, а не наступление календарного дня.

## Правила версий
- Формат `major.minor.patch`: `0.x.0` — этапы разработки; `1.0.0` — принятый законченный MVP. Исправления принятой версии увеличивают patch, например `0.3.1` или `1.0.1`; следующий этап сохраняет назначенный номер.
- Версия 0.1.0 относится к спецификации. Начиная с 0.2.0, перед передачей билда Engineer указывает соответствующую версию в Unity Player Settings и build notes; Android version code увеличивается для каждого нового устанавливаемого билда. Сейчас настройки Unity не меняются.
- Producer фиксирует принятую версию и evidence в CURRENT_STATE после review. Номер в таблице не означает, что этап уже завершён или билд существует; mock integrations не закрывают 0.6.0.
- Резерв необязателен и не означает автоматический выпуск 1.0.1. Сначала закрываются blockers предыдущих этапов; дополнительных feature milestones в резерве нет.

## Реалистичные варианты
Одна неделя — playable prototype с mock integrations, не полный commercial-like MVP. Полный заявленный DoD планируется на 2–3 недели. Если PluginYG2 не покрывает Android или задерживается импорт, можно продолжать независимые задачи с fake providers, но этап реальных интеграций и финальный gate остаются blocked. Producer предлагает пользователю конкретное решение по target/provider и влиянию на сроки.

После каждого gate Producer обновляет backlog и CURRENT_STATE. Проваленный gate нельзя назвать completed по наличию кода. К концу дня 4 переоцениваем план по скорости производства и состоянию Android build; при угрозе срокам уменьшаем количество upgrade уровней, VFX и презентационных материалов, сохраняя полный пользовательский сценарий.
