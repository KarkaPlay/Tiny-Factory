# Roadmap

Отсчёт — с начала production, не с bootstrap. Базовый план: 10 рабочих дней; до 5 дней резерва. Это оценка одного разработчика с виртуальными специалистами, не обещание параллельной скорости. Дни включают review и исправления.

0.1.0 принят 2026-10-05 как документный результат M01. 0.2.0 принят 2026-10-05 как техническая основа M02: UI/save решения, PluginYG2 matrix и назначенная Yandex Mobile Ads, Editor smoke и успешный Android APK code 4 после импорта RewardedAdv/InterstitialAdv, QA/provider PASS ([BUILD_NOTES](BUILD_NOTES.md), [M02_QA](M02_QA.md)). 0.3.0 принят 2026-10-05 для Editor/build scope: базовая цепочка и Speed L1, точная трасса/очереди и synthetic UI purchase PASS, Android APK code 6 ([M03_IMPLEMENTATION](M03_IMPLEMENTATION.md), [M03_QA](M03_QA.md)). 0.3.1 принят для Editor/build scope как патч читаемости M03-R01: DOTween presentation, очереди/lifecycle и три portrait формата проверены, APK code7 собран ([M031_QA](M031_QA.md)). По D12 физический install/run отложен до ручной проверки пользователя. Следующие версии — целевые, ещё не выпущенные; сроки сохраняются, версия обозначает принятый результат, а не календарный день.

## Правила версий

- Повторная оценка M03 по пользовательской обратной связи выявила недостаточную читаемость происходящего. Проверки симуляции и APK сохраняют PASS; понятность первого playable для новичка не подтверждена. Пользователь поручил и получил ограниченный patch 0.3.1 (M03-R01): presentation исправлен, Editor/build gate принят. Реальное понимание новичком и Android device UX остаются pending; сроки не переоценивались.
- Формат `major.minor.patch`: `0.x.0` — этапы разработки; `1.0.0` — принятый законченный MVP. Исправления принятой версии увеличивают patch, например `0.3.1` или `1.0.1`; следующий этап сохраняет назначенный номер.
- Версия 0.1.0 относится к спецификации. Начиная с 0.2.0, перед передачей билда Engineer указывает соответствующую версию в Unity Player Settings и build notes; Android version code увеличивается для каждой новой попытки сборки. В M02 настройки Unity уже изменяются по production-запросу пользователя; фактический результат сборки фиксируется отдельно от номера версии.
- Producer фиксирует принятую версию и evidence в CURRENT_STATE после review. Номер в таблице не означает, что этап уже завершён или билд существует; mock integrations не закрывают 0.6.0.
- Для 0.2.0 и текущего 0.3.0 пользователь разрешил проверки в движке и отложил подключение устройства (D12). Приёмка Editor-основы не означает готовность Android: APK, установка, запуск и performance имеют отдельные фактические статусы; финальный DoD по устройству сохраняется.
- Резерв необязателен и не означает автоматический выпуск 1.0.1. Сначала закрываются blockers предыдущих этапов; дополнительных feature milestones в резерве нет.

## Реалистичные варианты
Одна неделя — playable prototype с mock integrations, не полный commercial-like MVP. Полный заявленный DoD планируется на 2–3 недели. Если PluginYG2 не покрывает Android или задерживается импорт, можно продолжать независимые задачи с fake providers, но этап реальных интеграций и финальный gate остаются blocked. Producer предлагает пользователю конкретное решение по target/provider и влиянию на сроки.

После каждого gate Producer обновляет backlog и CURRENT_STATE. Проваленный gate нельзя назвать completed по наличию кода. К концу дня 4 переоцениваем план по скорости производства и состоянию Android build; при угрозе срокам уменьшаем количество upgrade уровней, VFX и презентационных материалов, сохраняя полный пользовательский сценарий.
