# Tiny Factory — Game Brief

Статус: дизайн MVP уточнён в M01; единый источник правил и чисел — [GAMEPLAY_SPEC](GAMEPLAY_SPEC.md). Pacing остаётся расчётной гипотезой до M03, не готовым балансом.

## Игровая фантазия и аудитория
Игрок превращает маленькую медленную фабрику в аккуратную автоматизированную линию и сразу видит результат каждого улучшения. Casual игрок, короткие мобильные сессии по 2–5 минут, управление одним пальцем. Portfolio project с качеством небольшой коммерческой игры; бюджет 1–3 недели.

Концепция M01 — карманная чайная мастерская: лист → сушилка → скрутчик → пакетирование/запайка с продажей. Один товар — пакетик чая, валюта — монеты; максимум четыре узла с источником. Один tap собирает сырьё; станки, транспорт и продажа автоматические. Конечные улучшения меняют время обработки, размер сбора и период автосбора. Первые цели и вся экономика описаны в GAMEPLAY_SPEC.

## Core loop и session loop
Сырьё → обработка → упаковка/транспорт → продажа → одна валюта → улучшение → быстрее видимый поток продукции.
Начало сессии: восстановление прогресса, понятная ближайшая покупка. Во время сессии: наблюдение выпуска, выбор доступного улучшения, открытие оставшегося звена. Завершение: надёжное сохранение. Idle в MVP означает автоматическую работу во время активной игры; offline earnings пока Post-MVP, а offline запуск и сохранение обязательны.

## Первоначальный MVP
- Одна фабричная сцена, фиксированная камера, одна цепочка и один тип готового товара; 2–4 звена обработки/транспортировки без ветвления.
- Один источник сырья, видимая обработка и доставка к продаже; ограниченный поток объектов без сложного AI/физической симуляции.
- Одна валюта. Три направления upgrades: скорость, производительность, автоматизация; конечные уровни с данными баланса, без бесконечного дерева.
- Две линейные ступени этой же цепочки: вставка скрутчика и превращение конечного стола в запайщик. Первая продажа до 10 секунд, первая покупка ориентировочно 30–60 секунд при расчётном ручном сценарии; арифметика проверена в M01, понимание и runtime timing проверяются в M03.
- Сохранение валюты, уровней, unlocks, onboarding и настроек; версия данных, восстановление после некорректного файла. Без сохранения каждого предмета на конвейере.
- HUD денег и доступных улучшений, короткое contextual onboarding, визуальный/звуковой feedback производства, продажи и покупки; выключение звука.
- Один добровольный rewarded placement: x2 монеты с продаж на 60 секунд активной игры. Лимиты, callback semantics и восемь analytics events — baseline GAMEPLAY_SPEC; M07 проверяет mapping после capability gate M02. Interstitial выключен по умолчанию; кандидат после unlock reveal ограничен caps и допускается только после UX/QA и platform proof.
- Малый набор событий аналитики с проверкой параметров и без персональных данных; Android playable build, материалы для портфолио.

## Visual direction и UX
Рабочее допущение: portrait, простая стилизованная 3D-фабрика в URP, читаемая сверху/под углом, цветом различаются сырьё и товар. Простые модели, повторно используемые материалы, иконки, короткие анимации и VFX. Смена камеры/ориентации требует оценки влияния на сроки. Не нужна большая библиотека уникального арта.

## Монетизация
Игровой цикл полностью доступен без просмотра рекламы. Rewarded усиливает существующий reward и требует явного выбора; награда выдаётся ровно один раз после подтверждённого завершения. Сбой/отмена/отсутствие сети не блокируют игру. Interstitial не прерывает покупку или tutorial. Требования и caps уточняются в M07 до реализации.

## Технический target
Найден Unity 6000.3.9f1, URP 17.3.0, Input System 1.18.0, uGUI 2.0.0. Версию сохраняем; UI stack окончательно выбирает Engineer с UI Designer в M02, без новой зависимости по умолчанию. Editor управляется через Unity MCP.
Android — целевой playable portfolio build. PluginYG2 добавит пользователь; использовать для всех подходящих возможностей после проверки версии, документации, платформ и callback semantics. Поддержка рекламы/аналитики Android ещё не подтверждена: M02 — обязательный ранний gate, без молчаливой замены SDK или смены target на WebGL.
Рабочая цель: стабильные 30 FPS минимум на выбранном до M03 среднем Android-устройстве; 60 FPS по возможности. Точное устройство, память и версия Android пока неизвестны.

## Защита scope
Без десятков уровней, персонажей и сложного AI, multiplayer, backend/accounts/social, narrative, большого tech tree, procedural generation, live ops, множества валют и enterprise architecture. Offline earnings, prestige, дополнительные фабрики и товары — Post-MVP.
Добавление в MVP требует причины, оценки времени и решения, какую другую работу убрать. При сокращении времени режем дополнительный polish, а не сохранение, читаемость, стабильность или честную проверку билда.
